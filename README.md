# PuppyGraph Supply Chain Demo

Load Eclipse Tractus-X part-instance test data into DuckDB and query its assembly relationships with PuppyGraph.

## How it works

| File | Role |
| --- | --- |
| `data/CX_Testdata_v1.7.0_PartInstance-reduced.json` | Original source data |
| `data/supply_chain_demo.db` | DuckDB database generated by the loader |
| `schema.json` | Mapping that tells PuppyGraph how to query the tables as a graph |

The loader converts the JSON into relational tables. PuppyGraph runs in Docker and accesses the generated database file directly. DuckDB does not need a separate server.

**The file uploaded to PuppyGraph is `schema.json`, not the source dataset.**

## Requirements

- Python 3.9 or newer, including `pip` and `venv`.
- Docker with Docker Compose. On macOS, install and open [Docker Desktop](https://docs.docker.com/desktop/setup/install/mac-install/).
- Bash and `curl`.
- Internet access for dependencies, the Docker image, and the DuckDB JDBC driver.
- Available local ports **8081**, **8182**, and **7687**.

The configuration uses PuppyGraph `1.13.0`, DuckDB Python `1.4.3`, and DuckDB JDBC `1.4.3.0`.

## Setup

Clone or download the repository and open its root folder in a terminal. Run all commands below from the directory containing `requirements.txt` and `docker-compose.yaml`. The commands use a macOS/Linux shell.

### Create the Python environment

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements.txt
```

If using VS Code, install Microsoft's Python extension, open **Python: Select Interpreter** from the Command Palette, and select `.venv/bin/python`.

### Load and validate the data

Confirm the original file is at `data/CX_Testdata_v1.7.0_PartInstance-reduced.json`, then run:

```bash
python3 scripts/load.py
```

Expected output:

```text
Validation passed: 499 parts (5 placeholders), 765 relationships.
```

This creates `data/supply_chain_demo.db`. The counts include 494 supplied items and five placeholder parts for referenced child IDs whose details are missing from the source.

### Start PuppyGraph and upload the schema

Open Docker Desktop and wait for its engine to run. Then execute:

```bash
docker compose version
bash scripts/start.sh
```

The startup script:

1. Checks that Docker is running and the database exists.
2. Starts the PuppyGraph container.
3. Waits for the API to become available.
4. Uploads `schema.json` automatically.

The first run downloads the image and JDBC driver and can take several minutes. If startup succeeds, **no manual schema upload is needed**.

Open [http://localhost:8081](http://localhost:8081) and sign in:

| Field | Value |
| --- | --- |
| Username | `puppygraph` |
| Password | `puppygraph123` |

These are local demo credentials. Ports bind to `127.0.0.1`. Stop any other demo using the same ports before starting this one.

### Manual schema upload (optional)

If you started the container with `docker compose up -d` instead of `scripts/start.sh`, upload the schema yourself:

1. Open **Graph → Upload Schema** in PuppyGraph.
2. Select the repository's `schema.json`.
3. If prompted about caching, choose **Do not cache data** to keep querying DuckDB directly.

You can also upload it from the terminal:

```bash
curl --fail-with-body --show-error \
  --user 'puppygraph:puppygraph123' \
  --header 'Content-Type: application/json' \
  --data-binary @schema.json \
  'http://localhost:8081/schema?postUploadBehavior=none'
```

The **Graph** page shows the model: `part` nodes connected by `contains` edges. View actual records and relationships through the **Query** page.

## Run queries

Open **Query**, choose **Cypher**, and run one statement at a time.

### Check the counts

```cypher
MATCH (p:part)
RETURN count(p) AS parts;
```

Expected: **499**.

```cypher
MATCH (:part)-[r:contains]->(:part)
RETURN count(r) AS relationships;
```

Expected: **765**.

```cypher
MATCH (p:part)
WHERE p.is_placeholder = true
RETURN count(p) AS placeholders;
```

Expected: **5**. These checks are saved in [`queries/01-check-counts.cypher`](queries/01-check-counts.cypher).

### Inspect parts and relationships

List a sample of supplied parts:

```cypher
MATCH (p:part)
WHERE p.is_placeholder = false
RETURN p.part_id, p.name, p.country
ORDER BY p.name, p.part_id
LIMIT 25;
```

Display a sample of assembly relationships as a graph:

```cypher
MATCH path = (parent:part)-[:contains]->(child:part)
RETURN path
LIMIT 25;
```

These queries are saved in [`queries/02-explore-parts.cypher`](queries/02-explore-parts.cypher). The relationship sample may vary between runs.

## Graph mapping

| Graph element | DuckDB table | Mapping |
| --- | --- | --- |
| `part` node | `supply_chain.part` | ID: `part_id` |
| `contains` edge | `supply_chain.contains` | ID: `edge_id`; `parent_id` → `child_id` |

The edge direction means **parent contains child**. IDs are also mapped as attributes, allowing queries to return or filter on `p.part_id`.

Part details come from `SerialPart` 3.0.0 and `Batch` 3.0.0. Relationships come only from `SingleLevelBomAsBuilt` 3.0.0. Other aspect models and top-level policies remain in the source JSON but are not mapped into this graph or enforced as access controls.

Placeholders have `is_placeholder = true`; missing descriptive details remain null. Source names, country codes, dates, quantities, and units are preserved. This is test data and may contain unrealistic names or assembly combinations.

The loader rebuilds the snapshot. Edge IDs are stable for unchanged input but depend on source array positions, so reordering arrays can change them.

## Stop, restart, and reload

Stop the container while retaining its state:

```bash
docker compose stop
```

Restart the existing container:

```bash
docker compose start
```

To reload the source data, stop PuppyGraph before opening the database for writing:

```bash
docker compose stop
source .venv/bin/activate
python3 scripts/load.py
docker compose start
```

Do not run the loader while PuppyGraph is using the DuckDB file. Extraction is transactional; snapshot-count validation happens after commit. Investigate any validation failure before restarting.

`docker compose down` removes the container and network while retaining the database file and PuppyGraph storage volume. Run `bash scripts/start.sh` to recreate the container and reapply the schema.

## Troubleshooting

Inspect container status and recent logs:

```bash
docker compose ps
docker compose logs --tail=80 puppygraph
```

| Problem | Action |
| --- | --- |
| `python` or `pip` not found | Use `python3` and `python3 -m pip`. |
| DuckDB module missing | Activate `.venv` and install `requirements.txt`. |
| VS Code uses the wrong Python | Select `.venv/bin/python` as the interpreter. |
| Docker engine unavailable | Open Docker Desktop and wait for it to start. |
| Port already allocated | Stop the application using 8081, 8182, or 7687. |
| Source JSON missing | Check the original filename and its location in `data/`. |
| Database missing | Run `python3 scripts/load.py`. |
| Database lock error | Stop PuppyGraph and close other connections before reloading. |
| Driver download fails | Check the container's access to `repo.maven.apache.org`. |
| Schema upload fails | Inspect the API error and container logs; confirm the file is `schema.json`. |
